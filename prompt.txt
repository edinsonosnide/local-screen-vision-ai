You are a senior software engineer and AI systems architect. Design and implement a fully local, privacy-first multimodal assistant application with the following requirements.

1. CORE OBJECTIVE

Build a desktop/web application that allows a user to:
- Share their screen
- Speak using a microphone
- Transcribe speech locally (STT)
- Process text using a local LLM
- Optionally analyze screen content using a local vision model
- Respond using local TTS (text-to-speech)
- Display all system activity (models, tokens, latency)

Constraint:
- NO external API calls
- NO internet dependency at runtime
- EVERYTHING must run locally

---

2. TECH STACK

Frontend:
- React + TypeScript
- Vite or Next.js (static export)
- Use:
  - getDisplayMedia (screen sharing)
  - getUserMedia (microphone)

Backend:
- Python (FastAPI) preferred OR Node.js
- Handles:
  - Model inference
  - Pipeline orchestration
  - Communication with frontend

---

3. MODEL ARCHITECTURE

All models must be stored locally in:

/resources

Structure:

/resources
  /stt
    /model_name
  /tts
    /model_name
  /vision
    /model_name
  /llm
    /model_name

Models:
- STT: Local Whisper or Hugging Face equivalent
- TTS: Local Hugging Face or lightweight engine
- Vision: Local multimodal model
- LLM: Local (GGUF via llama.cpp or transformers)

---

4. PIPELINE

1. User opens app
2. App requests microphone + screen
3. Audio → STT → text
4. Screen → Vision model → context (optional)
5. Text + context → LLM
6. LLM output → TTS
7. Audio response returned to user

---

5. UI REQUIREMENTS

Display:
- Active model names (STT, TTS, Vision, LLM)
- Token usage (input/output)
- Latency:
  - STT
  - LLM
  - TTS
- Live transcription
- LLM response text
- Debug logs

---

6. CONFIGURATION

Provide config file:

/config/models.json

Example:
{
  "stt": "whisper-small",
  "tts": "coqui-tts",
  "vision": "gemma-vision",
  "llm": "llama-3"
}

---

7. COMMUNICATION

Use:

Option A (Preferred):
- REST API (FastAPI)
  - /stt
  - /llm
  - /tts
  - /vision

Option B:
- WebSockets (for streaming)

---

8. PERFORMANCE

- Must run on 16–32 GB RAM systems
- Support quantized models
- GPU optional, CPU fallback required

---

9. SECURITY

- No telemetry
- No external communication
- All data remains local
- Explicit user permissions required

---

10. DELIVERABLES

- Full project structure
- Backend implementation
- Frontend implementation
- Model loading system
- Example placeholders
- Setup instructions
- README with architecture and usage

---

11. OPTIONAL FEATURES

- Wake word activation
- Streaming responses
- Overlay UI
- Plugin/tool system
- Local memory (vector DB)

---

12. FINAL CONSTRAINTS

- No OpenAI API
- No Hugging Face API
- No cloud services
- Only local inference
- Models must load from /resources

---

Write clean, production-ready code with clear modular architecture and comments explaining model integration.
